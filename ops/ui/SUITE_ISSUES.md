## KeepIt sketchbook · 25 November 2026 (KI-010, KI-011)

- Owner request (25 Nov): "Can you develop the iconography and make it look nicer? I want a full screen view when I draw."
- The sketchbook now covers the whole screen. The page fills the available width behind floating, translucent controls: close and undo/redo top left, view controls and Insert/Update top right, and a tool dock at the bottom. Phones stack the view controls above the tool dock. Full screen also asks the browser to hide its own UI where allowed (Mac and iPad Safari). iPhone Safari uses the in-app immersive layout. Controls fade while ink is going down.
- New consistent 24-unit outline icon set (inline SVG, no font/CDN): fountain pen, pencil, marker, highlighter, line, eraser, layers, paper, ruler, full screen, undo/redo, eye/eye-off. Tool nibs take the current ink color. 44 px targets, accessible names, keyboard arrow navigation between tools, and selected state shown by lift, dot and color (not color alone). Follows the suite appearance scheme, including Midnight.
- Compact popovers replace the two rows of text buttons. Ink has swatches, the color wheel, hex, a live stroke preview, and thickness/opacity sliders. Each tool remembers its own size and opacity. Layers has a list with per-layer show/hide, rename and raise/lower. Paper has size, guides and custom mm. View has fit width, fit whole page and Export PNG.
- Leaving with unsaved ink offers Insert/Update, Discard or Keep drawing. An unchanged revision closes silently. Escape steps back one level. ⌘Z, ⇧⌘Z and ⌘↩ are scoped to the sketchbook, never while typing in a field. Mac trackpad pinch zooms. The ruler appears in the middle of the visible area. Reopening a drawing whose saved active layer is hidden starts on the top visible layer.
- Unchanged: the stroke model, the kiNt PNG payload (version 1), layers/visibility/order, paper rescaling, ruler double-tap, two-finger navigation, pressure/tilt, the canonical note writer and `editDrawing`. New `keepit-sketchbook.browser.mjs` asserts payload round-trip, revision equality, discard safety, legacy raster PNG and touch-target size at iPad and phone widths.
- Pending: WebKit run in CI, real iPad Air M4 + Pencil Pro check (native full screen inside the installed PWA, palm rejection, orientation) and phone review.
- Follow-up (25 Nov, owner): "I need to be able to specify resolution, current resolution is poor. Also fix the color contrast." Paper now has a Resolution setting: Standard 150, High 220, Print 300 (default for new drawings), Ultra 400, or custom 72–600 dpi, with the pixel size shown. Pixels are capped at 16 MP and 8192 px per side to stay within iPhone/iPad Safari canvas limits, and the panel says when a large paper size is held back. The effective dpi is saved in the page (optional `dpi` field, still version 1). Pages saved without it reopen on their original grid. Changing resolution or paper keeps stroke size on paper. Stroke widths scale with dpi, so 300 dpi ink matches the old physical thickness. Known limit: an older cached build revising a high-dpi page will misplace strokes until it updates.
- Contrast: ink-coloured icon parts (nibs, line ends, highlighter bar, colour dot) are filled with ink and outlined in the icon colour, so they stay visible on any scheme. Disabled controls are stronger. Controls fade less while drawing. The current layer uses text colour plus an accent bar. An automated audit (3:1 icons, 4.5:1 text, 2:1 disabled) passes for the default, Journal, Midnight, Linen, Lavender and Forest schemes.
- Fixed: closing a panel returned focus to the page body, so ⇧⌘Z stopped working. Focus now returns to the panel's button, and shortcuts are captured while the sketchbook is open.
- Layers (25 Nov, owner): "page background opacity, drawing opacity, blending mode, copy, duplicate, merge selected layers … ability to organize which layers go on top." The Layers panel now has:
  - thumbnails, a drag grip to reorder (top of list = on top; arrow keys on the grip also work), plus Move to top, Raise, Lower and Move to bottom;
  - per-layer name (inline, no prompt), opacity and 16 blend modes (canvas composite operations, WebKit-supported);
  - Duplicate, Copy and Paste (the clipboard lasts the app session, so layers can move between drawings and notes; the PNG also goes to the system clipboard where allowed), Merge down and Delete;
  - a Select mode for merging or deleting several layers;
  - a Background row with paper opacity. The inserted PNG keeps the transparency, and the canvas shows a checkerboard.
- Merge composites the chosen layers (bottom to top, with their opacity and blend) into one pixel layer, stored as `raster` (PNG data URL) on the layer. The result is pixel-identical, verified by test. New ink can still be added on a merged layer, and undo restores the separate layers.
- Undo/redo now covers strokes and every layer change (add, delete, duplicate, paste, merge, reorder, visibility, name, opacity, blend, background opacity) in one history. Existing strokes of a reopened drawing stay undoable as before. A resolution change rescales strokes held in history too.
- Payload stays version 1 with optional fields: `layers[].opacity`, `layers[].blend`, `layers[].raster` and `paperOpacity`. Older pages load with defaults. Known limit: an older cached build would ignore these when revising.

### KI-012 Pencil capture, pressure and pastel palette (sketchbook)
- Reported on iPad Air M4 + Pencil Pro: some strokes (small lowercase letters) were not captured; line weight/opacity did not follow pressure; default colours too bold.
- Capture: a new pen contact always ends any stale stroke instead of being ignored; the pen is followed on the whole dialog (not only the canvas), a lost pointer capture is re-taken, cancelled/hover-ended strokes keep their points. More > Pen check reports strokes down/lifted/cancelled/replaced, pressure range and skipped contacts.
- Speed: only the area a stroke touched is recomposited (was the whole 8.7 MP page on every move at 300 dpi); straight lines preview without replaying the layer.
- Pressure: smoothed Pencil pressure drives line weight (Pen, Pencil, lightly Marker) and pencil softness; Ink panel has Pencil pressure Off/Light/Normal/Strong. Opacity is now exact for new strokes (older strokes keep their saved look). Points may carry `a` (softness); strokes carry `soft:1`.
- Palette: ink navy, black, graphite, then soft Copic-style pastels. Highlighter default 45%, Pencil 80%.
- Test: partners/connected/keepit-sketchbook-pen.browser.mjs (synthetic pen events). Not verified: real Apple Pencil Pro on device, WebKit.
- KI-012 follow-up (same day): strokes had visible dots with translucent tools and words were still being lost. Strokes are now smoothed curves filled as one shape per frame; translucent strokes are laid on the page once at their opacity (even, no beads). Pointer handlers only record samples (drawing happens per frame from the record, so a slow frame cannot miss the next stroke). Removed the live blur behind the toolbars and the fade while inking (costly on iPad). Pencil pressure now changes line weight only. Pen check also compares Pencil contacts the page received with strokes drawn, slowest frame and handler errors.
- KI-012 follow-up 2: letters still lost right after a lift. Likely cause found: every lift triggered a repaint of the whole 300 dpi page, stalling the page exactly when the next stroke began; lifts now repaint only the stroke's area, and explicit pointer capture was removed. Ink now looks hand-drawn: pen width follows pressure (auto-ranged to the user's hand) and speed with an eased entry; marker and highlighter have a flat chisel tip; pencil has paper grain. Pen check shows the last Pencil events.

- KI-002/KI-003 (owner report 25 Nov: Home Screen app stays white forever on iPad). Cause: the service worker answered every page and mutable script network-first with no time limit, and waited for each response to be saved before handing it over, so a stalled connection after the app wakes left the page blank indefinitely (reproduced: old worker blank >30 s with stalled requests). Fix: wait at most 2.5 s for the network, then use the saved copy (the shell is also saved under its path so the newest copy is used); save in the background; if nothing is saved and the network never answers, show a "Couldn't reach your apps — Try again" page after ~27 s. Test: keepit-shell-worker-stall (fails on old worker). Not verified on a physical iPad.
- KI-001 (OneDrive login loops/disconnects, esp. installed iPad/iPhone app). Cause found: bundled MSAL Browser v5.25 encrypts its localStorage sign-in cache with a key kept in a session cookie (`msal.cache.encryption`, no expiry) unless the Microsoft sign-in carries "Keep me signed in". When the browser session ends (an installed app is closed), the key is lost, MSAL creates a new one and silently discards the saved sign-in, so KeepIt shows Connect/Reconnect again. Reproduced with the real bundled MSAL: old build expires=-1 and a different key after the session ends. Fix (auth.js): renew the key cookie with a 400-day expiry on every launch and keep a local backup restored before MSAL starts; backup removed on sign-out. Trade-off: the saved sign-in is protected like MSAL's own "Keep me signed in" mode. Test: keepit-auth-key (real MSAL, fails on old build). Needs one more Microsoft sign-in after deployment, then physical-device confirmation.
- KI-004 (owner 24 Nov: first edit arrives ~30 s, later edits stale). Reproduced with two simulated devices: Mac→iPad edits arrived, then the first iPad→Mac edit never arrived and the Mac's next save failed with "This note changed on another device"; from then on neither device received the other's edits. Causes: (1) a note left open in the editor (Save keeps the editor open) was never refreshed, so the next save there was based on an old version and conflicted; (2) after saving with Save, the reader kept a draft identical to the saved note but still based on the previous version, which counted as unsaved work and blocked every later refresh; (3) the 30 s check skipped a reader still marked pending after its own save. Fix: an open editor with no unsaved changes moves to the newer version (unsaved typing is never replaced; it shows that a newer version exists); a retained draft identical to the saved note is discarded; a pending reader completes its save then refreshes. Test: keepit-sync-roundtrip (5 alternating edits, each must arrive within 45 s; fails on old code at the first iPad→Mac edit). Not verified on physical devices.

## 2026-11-27 · Heavy PDFs lock the item window (reported on iPad)

- Symptom: with some large, picture-heavy PDFs the preview lags, then Write beside, Download original, Keep offline, Save changes, the page arrows and the close (X) button all stop responding.
- Cause: page turns ran under the library-wide operation lock, which disables every button including Close, and Close refused to run while that lock was held. When iPadOS runs short of memory it can stop the PDF worker silently, so a page render never settles and the lock never lifts.
- Fix: page turns are reader-local; each page render has a 20 s budget and then shows a message; Close and Escape work unless a change is being saved; closing the reader is bounded to 3 s.
- Test: `partners/connected/keepit-pdf-stuck-page.browser.mjs` (fails on the previous release).
- Still open: render cost of very heavy pages on iPad (lag) — measure on device.
